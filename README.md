# Yandex Music Downloader Plus

**Windows-приложение для загрузки, восстановления и резервного копирования музыкальной библиотеки Яндекс Музыки.**

Основной интерфейс — графическое приложение WPF. Консольная оболочка PowerShell сохранена как дополнительный диагностический режим. Оба интерфейса используют один и тот же движок, логи, отчёты, DPAPI-хранилище токена и backend-модули.

> Программа не содержит личных токенов, cookies или ссылок на плейлисты. Источник пользователь указывает сам. Не добавляйте секреты и личные логи в Git.

## Установка

Скачайте **[Yandex Music Downloader Plus 0.3.0 для Windows](https://github.com/Andreyfdfd/YandexMusicDownloaderPlus/releases/tag/v0.3.0)** и запустите YandexMusicDownloaderPlus-Setup-0.3.0.exe.

Установщик включает графическое приложение Windows, PowerShell-движок и консольный запуск, переносимый CPython 3.14, основной загрузчик и независимый API backend, резервный yt-dlp-плагин (его можно предустановить компонентом) и инструкции.

Отдельно устанавливать Python, Git или pip не нужно. WPF-клиент рассчитан на Windows 10 22H2 / Windows 11 и использует .NET Framework 4.8, присутствующий в поддерживаемых версиях Windows.

В мастере установки выбираются каталог программы, компоненты, ярлык и музыкальная папка. По умолчанию музыка сохраняется в %USERPROFILE%\Music; создание папки во время установки можно отключить. По умолчанию ярлык запускает графическое приложение. В меню Пуск также доступен отдельный пункт «Консольная версия».

Установщик не подписан сертификатом издателя, поэтому Windows SmartScreen может показать предупреждение. Контрольная сумма SHA-256 опубликована рядом с EXE.

## Графическое приложение

В приложении есть шесть основных разделов:

- **Загрузка музыки** — URL плейлиста, альбома, исполнителя или трека, папка библиотеки, формат, тексты песен и задержка запросов. Показывает текущий вывод, прогресс и позволяет отменить операцию.
- **Экспорт библиотеки** — сохраняет список треков без скачивания аудио.
- **Восстановление** — выбирает предыдущий журнал загрузки и повторяет только проблемные позиции.
- **Неудачные треки** — список проблемных композиций выбранного запуска. Можно повторить одну песню или весь список, а также открыть веб-поиск официальных источников по названию и исполнителю.
- **Журналы и отчёты** — открывает логи, очереди, CSV пофайловых результатов и сводки.
- **Настройки** — сохраняет токен и музыкальную папку в профиле текущего пользователя Windows.

Браузерный резервный способ отключён по умолчанию. При его включении приложение дополнительно спрашивает разрешение на использование cookies выбранного браузера. Это отдельное согласие, потому что браузерная сессия предоставляет локальному процессу доступ к авторизованному аккаунту.

## Загрузка и резервирование

Порядок попыток для проблемной композиции:

1. Основной yandex-music-downloader.
2. Независимый API-клиент, встроенный в пакет.
3. yt-dlp с браузерной сессией — только после явного согласия.

Основной downloader запускается через небольшой Go launcher. Для встроенной версии токен передаётся дочернему Python через временную переменную окружения и внедряется уже после старта процесса, а не помещается в командную строку процесса.

Для каждого резервного аудиофайла проверяются чтение и длительность относительно метаданных. Короткие preview, неполные и нечитаемые результаты не подменяют существующую библиотеку: они сохраняются в карантине или staging. В ходе автоматического восстановления непустые файлы с неподходящей длительностью могут быть перемещены в соседнюю папку карантина, но не удаляются. Файл с неизвестной длительностью автоматически не трогается.

**Ограничения доступа не обходятся.** При HTTP 401/403/429, явном not-allowed, DRM, недоступности композиции, ограничениях подписки или региона переключение backend не используется для обхода отказа. Ошибка 404/playlist-not-found может быть проверена независимым клиентом с тем же аккаунтом: она может быть следствием несовместимого маршрута или парсинга, а не запрета доступа.

## Экспорт библиотеки без аудио

В графическом интерфейсе откройте «Экспорт библиотеки» и укажите ссылку и папку. Создаются четыре файла:

| Формат | Назначение |
|---|---|
| CSV | Перенос в Soundiiz и совместимые медиасервисы, таблицы |
| JSON | Полная резервная копия Downloader Plus |
| TXT | Строки Исполнитель - Название |
| XML | Структурированный список композиций |

Сохраняются название и версия трека, исполнители, альбом, длительность, ISRC при наличии, порядок в источнике, ID и ссылка. Аудиофайлы не скачиваются, токен в файлы экспорта не включается. По умолчанию файлы сохраняются в Документы\YandexMusicBackups.

## Отчёты и диагностика

В logs создаются:
- download-*.log — полный ход запуска;
- source-inventory-*.csv — снимок состава источника;
- library-status-*.csv — удалённые из источника и неподтверждённые позиции;
- unavailable-*.csv — треки, которые источник объявил недоступными;
- file-outcomes-*.csv — наблюдаемые результаты по аудиофайлам;
- retry-queue-*.csv и recovery-results-*.csv — ход восстановления;
- errors-*.txt — итоговая диагностическая сводка.

Сравнение удалённых композиций начинается после первого успешного снимка того же URL. Если API не позволяет получить полный список, загрузка может продолжиться, но сравнение состава будет неполным. Точный счётчик файлов, молча пропущенных основным загрузчиком, upstream не предоставляет.

## Токен и безопасность

Токен хранится в %APPDATA%\YandexMusicDownloaderPlus\token.dpapi, зашифрован Windows DPAPI для текущего профиля. GUI использует то же хранилище, что и PowerShell-оболочка; перенос файла на другой ПК или в другой профиль Windows не гарантирует расшифровку.

Для встроенного основного launcher токен не включается в аргументы командной строки. Он временно доступен процессу PowerShell и передаётся дочернему процессу через окружение. Внешний upstream CLI из исходного/developer-сценария может требовать токен как аргумент; для обычного установленного графического приложения используется bundled launcher.

Не коммитьте token.dpapi, cookies, токены, личные ссылки и логи. Перед отправкой диагностического файла третьим лицам просмотрите его на предмет персональных URL и данных аккаунта.

## Консольный режим и разработка

Графическое приложение — рекомендуемый способ обычного использования. Для диагностики можно выбрать в меню Пуск «Консольная версия» или запустить Запустить_загрузку.bat.

Для разработки из исходников нужны Windows 10/11, PowerShell 5.1+, Python 3.14 и Go 1.24 для сборки native launcher. WPF-проект находится в ui/DownloaderPlus и собирается на Windows через .NET SDK; целевой фреймворк — .NET Framework 4.8.

## Текущие ограничения

1. GitHub CI проверяет сборку, импорты, сериализацию файлов и тестовую установку, но не выполняет аутентифицированную загрузку через личный аккаунт Яндекса. Такой сетевой тест выполняется на ПК пользователя.
2. API и схема ответов Яндекса могут изменяться. Независимый клиент уменьшает зависимость от основного CLI, но не гарантирует доступ к каждому треку.
3. Метаданные источника могут быть неполными, а ненулевой файл с правильной длительностью всё ещё может содержать ошибку кодирования или тегов. Для важных записей сохраняйте возможность ручной проверки.
4. Отчёт о снятых с публикации или удалённых из плейлиста треках требует как минимум одного успешного исходного снимка.
5. Если источник недоступен самому аккаунту, приложение сообщает отказ и не пытается обходить права или ограничения сервиса.

## Структура проекта

- YandexMusicDownloader.ps1 — общий orchestration/backend слой и консольная оболочка.
- ui/DownloaderPlus — WPF-приложение Windows.
- tools/launcher — native Go launcher для встроенного Python CLI.
- tools/source_inventory.py — снимки состава источников, экспорт и проверка длительности.
- tools/backends — независимый API backend, CLI-мост и сведения о лицензии.
- installer — Inno Setup и воспроизводимый Windows build.
- .github/workflows/release-windows-installer.yml — Windows CI и публикация релиза.
